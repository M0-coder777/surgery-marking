# 开发范围说明 · 功能验证版本（V0.5 全身部位层）

> 交付目标：**验证 3D 标记的展示效果与三方核查交互**，不是可上线的临床系统。
> 本文档与系统内「范围说明」标签页内容一致。
> 版本沿革：V0.1 程序化模型基础版 → V0.2 按分区整块选中 → V0.3 接入真实肌骨模型 → V0.4 脏器 + 骨骼 + 腹部九分区 → **V0.5 全身部位层（本版）**。

## 一、本期定位

| 项 | 结论 |
|---|---|
| 用途 | 术前沟通与核对流程的**交互验证**，标记打在标准解剖模型上 |
| 模型 | **两层内置模型**，坐标系统一对齐（同为 Z-Anatomy 图谱原点，身高 1.696 m）：<br>① **脏器层** `organs-bones.glb`（20.5 MB）：1148 个可标记结构（骨骼 626 / 脏器 137 / 脑与神经 385），约 161 万三角面；<br>② **部位层** `body-regions.glb`（0.72 MB，V0.5 新增）：250 个体表分区皮面（图谱自带「人体分区」体系），归并为 **34 个体表部位**，左右各 125 |
| 模型口径 | **不含肌肉**、不含血管神经主干、不含皮肤被盖；部位层是**体表分区皮面**（用于标注体表分区的曲面），不是解剖学意义上的皮肤 |
| 数据 | **不记录任何患者身份信息**，不与 HIS 对接，数据仅存本机浏览器 |
| 合规口径 | 展示/沟通工具验证版；不参与实际手术决策，文案避免"诊断/导航/精准定位" |
| 角色 | 开单医生 / 主刀医生 / 手术室护士（模拟登录身份切换） |

## 二、本期包含（IN）

- **「骨骼 + 脏器」解剖模型（V0.4）**：按用户需求把模型从肌骨系统（含肌肉）换为只含**脏器 + 骨骼（+ 脑与神经）**的子集；浏览器加载 + 解码约 2–4 秒；支持「模型半透明」透视观察深层结构。
- **体表部位层升级为全身（V0.5 新增，本期核心）**：
  - 数据源是图谱**自带的权威分区体系** `人体分区.g`（提取为 `models/body-regions.glb`，250 个体表分区、244 个唯一几何 / 23,105 面、左右各 125，全中文命名，无毛发与标注残留）；
  - 由 `src/regions.js` 的**归并表**归并为 **34 个体表部位**：头颈 2 · 胸 2 · **腹 9（临床九分区）** · 背 2 · 会阴 1 · 上肢 8 · 下肢 10，**全部区分左右**（右上臂 / 左上臂是两条）；
  - 腹部沿用**临床九分区**口径：右季肋区（右上腹）、腹上区（上腹部）、左季肋区（左上腹）、右腰区（右侧腹）、脐区（脐周）、左腰区（左侧腹）、右髂区（右下腹）、腹下区（下腹部）、左髂区（左下腹）；其中「腰区 ≈ 图谱腹外侧区」「髂区 ≈ 图谱腹股沟区」为近似对应，其余部位按图谱解剖分区命名；
  - **可下钻**：每个部位可展开查看其包含的图谱细分分区（如「左上臂」= 臂前区 / 臂后区 / 肘前区 / 肘窝 / 肱二头肌内侧沟 / 肱二头肌外侧沟，共 7 个；「头部」= 82 个），细分分区同样可整块选中与标记；
  - 与普通结构同样支持**悬停预览 / 整块选中 / 一键标记整个部位 / 标记部位中心**，标记只锚定 `{ regionKey }`，位置取分区质心。
- **三态层级切换（V0.5 新增）**：面板顶部「**全部 / 仅部位 / 仅脏器**」——全部（部位半透明外壳叠加在脏器骨骼之上，可同时看体表与深层）/ 仅部位（只看人形分区色块，便于按部位选点）/ 仅脏器（只看深层结构）。切换联动**可见性、拾取目标、部位高亮缓存与已有标记显隐**；切到「仅脏器」时体表部位的标记一并隐藏，不留悬空标记。
- **类别显隐（V0.4）**：面板顶部「骨骼 / 脑与神经 / 脏器」三类结构可独立开关（默认隐藏脑与神经）；显隐联动**拾取列表、结构高亮、体表部位高亮缓存与已有标记**。
- **结构级整块选中（V0.2 引入）**：
  - 「按部位」面板：结构按体区分组，体表部位按**身体大组**（头颈部 / 胸部 / 腹部 / 背部 / 会阴部 / 上肢 / 下肢）置顶，带左右徽标与图谱分区计数；
  - 搜索：中文名（如「肝」「股骨」「前臂前区」）、拉丁名、分组名、部位别称与图谱细分分区名，及「右 脏器」这类**侧别 + 关键词**组合；搜索命中细分分区时单独列出「图谱细分分区」分组；
  - 悬停清单项 → 模型上**整块预览**；单击 → 整块选中（实色高亮）并自动正对（部位类相机最小距离加大，避免穿模）；
  - 「部位」工具（快捷键 B）：在模型上**单击任意位置即整块选中**该处所属结构或体表分区（「全部」模式下部位层优先）；
  - 一键「**标记整个结构 / 部位**」（全部面片作为区域标记，范围即真实几何范围）或「**标记中心**」（质心投射锁定到该结构自身表面；长骨等包围盒中心在体外的结构自动做多方向兜底，仍不中则明确提示改用「标记整个结构」，**绝不改锚到别的结构上**）。
- **点标记**：结构表面单击取点，支持类型（切口/切除范围/穿刺点/引流/注意禁区/其他）、侧别、名称、备注。
- **区域标记**：表面连续取点（≥3）闭合成**贴合曲面的面片**；限定在同一解剖结构上取点，避免跨凹陷悬空。
- **防漂移锚定**：点标记以 `结构id + 面索引 + 面内重心坐标` 锚定；按结构 / 体表部位 / 图谱细分分区生成的标记以 `{ regionKey }` 锚定。实测：视角旋转、极限缩放、**三次层级切换**、类别显隐开关后标记三维坐标完全不变（逐位一致）。
- **距离测量**：两点间距（mm，模型为真实米制尺寸；仍不代表患者个体解剖尺寸）。
- **方案版本管理**：草稿 → 待核查 → 已冻结 / 已退回；冻结后只读，修改须新建修订版；每版带防误改校验码（FNV-1a，非签名）。
- **三方核查**：三方分别独立核对 4 项核查点；三方一致 → 自动冻结；任一异议 → 退回。
- **操作留痕 / 本地存储与 JSON 导入导出 / PNG 截图导出**。
- **隐私字段自检**：每次落盘与导出前机械扫描禁用键，命中即阻断。
- **离线可用**：模型、Three.js、Draco 解码器全部本地化；`file://` 直开自动降级为「选择 / 拖入模型文件」，功能一致；**部位层加载失败可降级**（仅脏器层照常可用）。

## 三、本期不含（OUT）

| 不含项 | 说明 | 后续接入方式 |
|---|---|---|
| **肌肉系统** | 应需求明确剔除；脏器层不含肌肉、肌腱、韧带、筋膜、滑囊 | 提取器保留规则加入 Muscle/Tendon 材质即可重新导出 |
| **皮肤与体表被盖** | 部位层提供的是**体表分区皮面**（图谱用于标注体表分区的曲面，有真实体表几何），**不是解剖学意义的皮肤被盖**，也未细分真皮 / 皮下层次 | 需要皮肤层时在提取器保留 Skin 材质 |
| **患者身份信息** | 数据结构中无对应字段，且有机械自检拦截 | 接 HIS 后在方案对象上增加患者引用（仅存 HIS 主键，不存明文） |
| **HIS 对接** | 不调用 HIS，无患者信息/手术申请/排程 | 在"登录鉴权→待标记列表→详情→提交前复核→状态回写"等时序点接入字段映射层 |
| **手术部位编码映射** | 不做部位名称与 ICD-9-CM-3 等编码的对照校验 | 在标记/方案上增加编码字段，提交前校验"部位—编码"一致性 |
| **电子签名** | 核查仅记录角色与时间，不构成法定签名 | 将角色确认记录替换为带证书的签名对象 |
| **手麻系统联动** | 不下发核对任务、不回写状态 | 数据模型已预留第四方角色位 |
| **患者个体化解剖** | 无 CT/MRI 重建，标记不等同于真实解剖定位 | 用分割重建模型替换标准模型，锚定算法不变 |
| **血管 / 神经 / 淋巴系统** | 脏器层提取时剔除非目标系统，避免遮挡脏器 | 同肌肉：调整提取器保留规则 |
| **深层结构联动高亮** | 应需求取消：选中体表部位**只高亮该部位皮面**，不再联动高亮其下方的脏器 / 骨骼（腹部大区仅在信息栏列出「区内结构」名称，供参考） | 如需恢复，在部位条目上挂 `organMembers` 并注册到高亮层即可 |

## 五、运行方式

- **静态服务器（推荐）**：`python -m http.server 8899` 后访问 `http://127.0.0.1:8899/`（自动加载两层模型）
- **双击 index.html**：浏览器禁止网页自动读取本地文件，会提示选择模型文件（先选 `models/organs-bones.glb`，可选再选 `models/body-regions.glb`），解析结果与服务器方式完全一致；不选部位层则自动降级为仅脏器层

数据保存在浏览器 localStorage；换浏览器/清缓存会丢失，可用「导出 JSON」备份。

## 六、扩展指南：如何增加一个体表部位

部位层是**数据驱动**的，加部位不需要重新导出模型：

1. **模型里已有该分区**（图谱 `人体分区.g` 的 250 个分区之一）→ 只需在 `src/regions.js` 的 `MAJOR` 里加一行 `{ key, code, name, alias, side, group }`，再在 `RULES` 里加一条归并规则（按 `sys` / `cn` / `side` / `under` 祖先链匹配），刷新即生效；
2. **模型里没有该分区** → 先在 Startup.glb 提取脚本（`.tmp-verify/extract-regions.py`）的保留名单里加入对应分区重新导出 `body-regions.glb`，再做第 1 步；
3. 大区键沿用 `part:` 前缀、细分分区沿用 `rg:系统/中文名.侧别`，标记锚定与清单 UI 无需改动。
